# ai_auto_nepse

A NEPSE market archive and analysis app, **Python only**, storing everything in plain
`.txt` files (no database). Fetches daily/minute OHLC and the broker-level floorsheet for
every listed symbol, aggregates broker flow, and serves it through a Streamlit UI with a
TradingView-style chart, scanner, and a volume-spike / broker-flow screen.

## Layout

| file | what it does |
|---|---|
| `fetch_symbols.py` | symbol + index lists → `Master_data/{symbols,indices}.txt` |
| `fetch_ohlc.py` | daily OHLC per symbol → `Master_data/<kind>/<SYM>/1D.txt` (also the shared helpers other scripts import) |
| `fetch_intraday.py` | 1-minute bars → `<SYM>/1minutes.txt` |
| `fetch_minutes_today.py` | exact 1-minute candles rebuilt from the day's floorsheet |
| `fetch_floorsheet_merolagani.py` | per-date floorsheet scrape → `Master_data/floorsheet/<SYM>/<DATE>.txt` |
| `build_broker_flow.py` | aggregate floorsheet → `Master_data/broker_flow/<SYM>.txt` (one row per date+broker) |
| `fetch_last_session.py` | fetch **one** session and upsert it into every store (idempotent) |
| `scan.py` | indicator signal scan → `Master_data/scan.txt` |
| `volume_spike.py` | volume-spike + broker-flow screen → `Master_data/volume_spike.txt` |
| `indicators.py` | SMA/EMA/RSI/MACD/ALMA/pivots/ATR/structure, pure Python |
| `naasa.py` | NAASA public datafeed client (instrument types, live quotes) |
| `daily_update.py` | runs every fetch/build step in order; append-logs to `update_log.txt` |
| `ui.py` | the Streamlit app |

## Run

```bash
pip install streamlit plotly pandas numpy
python daily_update.py     # build/refresh the Master_data archive (first run is long)
streamlit run ui.py        # open the app at http://localhost:8501
```

## Data

`Master_data/` (~5.8 GB, 300k+ files) is **not** in the repo — it is fully regenerated by the
fetch scripts above. `daily_update.py` builds it from scratch; the in-app **Cron** page runs
the same steps on demand.

## Notes

- **Python only, `.txt` only** — no other language, no database. See `CLAUDE.md`.
- The NAASA token, if used, is read from the `NAASA_TOKEN` env var and never written to disk.
- The volume-spike screen is an **activity** screen, not a buy list: a flagged window has
  usually already made its move, and NEPSE's floorsheet carries broker IDs, not client IDs,
  so concentration cannot prove a single operator.
